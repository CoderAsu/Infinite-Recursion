PULL REQUEST WORKFLOW

A pull request (called a merge request on some hosting sites) asks others to review and integrate a branch. It is a hosting-site workflow built around Git branches and commits.

Typical workflow:
1. Update the base branch: git switch main, then git pull.
2. Create a feature branch: git switch -c feature/short-description.
3. Make a focused change, inspect it with git diff, then stage and commit it.
4. Push the branch: git push -u origin feature/short-description.
5. Open a pull request on the hosting site, choosing the base branch (often main) and your feature branch.
6. Explain what changed and how you checked it. Respond to review feedback with more commits and push them to the same branch.
7. After approval and required checks pass, merge using the project's agreed method.
8. Update your local main branch and delete the feature branch when it is no longer needed.

Follow the project's contribution instructions and branch protections. Do not force-push to a shared branch unless the team has agreed.
