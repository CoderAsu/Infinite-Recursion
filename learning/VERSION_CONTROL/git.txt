To know who we are: git config

git config user.name --> current repository only
git config --global user.name --> all repositories for your user account
git config --system user.name --> all users on the computer

To remove the name we have to use --unset
for example: git config --global --unset user.name

To check whether we have added a name/email or not --> simply write the commands given above without "name"

git config --global user.name "name"
git config --global user.email "abc@gmail.com"









git init --> adding local git repository (hidden) (also create main branch)
rm -rf .git --> to remove the local git repository

git status --> whether the file is in staging or non-staging area
git status -v --> v means verbose/detailed information
git status -s --> s means short information

A --> added i.e it is in staging area
?? --> it is in non-staging area
M --> modified
D --> deleted

git add filename --> to add a file in staging area (git is aware of the files)
git add . --> to add all files in staging area
git restore --staged <file> --> to unstage files
git rm --cached <file> -> remove a file from Git's index
git commit -m "message" --> track

git commit -a -m "message" / git commit -am "message" -> when we modified a file which is already tracked
git commit --amend --> to attach the latest commit with existing commit

git commit -s -m "message" --> to sign-off which was seen by senior
git commit --allow-empty -m "message" --> it doesn't change any files, but still creates a new commit






git log --> to see the commit details

git show <commit_id> --> displays the details of a specific commit, including its commit message, author, date, and the changes (diff) introduced by that commit.



git log -n number -> to see how many commit

git reset --soft <commit_id> --> undo the changes to staged area
git reset --mixed <commit_id> / git reset <commit_id> --> undo the changes to unstaged area
git reset --hard <commit_id> --> removes the last commit and deletes changes from staging and working directory
git revert <commit_id> --> does not remove commits. Instead, it creates a new commit that undoes the changes from a previous commit.



* If the commit exist only locally, git reset is usually appropriate. If the commit was already push then use git revert.


git reset --mixed/--soft/--hard HEAD~1 --> first commit will reset
git reset --mixed/--soft/--hard HEAD~2 --> second commit will reset
































# Branches are always associated with commits

git branch <branch_name> --> to create a branch
git branch <branch_name> <commit_id> --> to create a branch from the specific commit
git branch -m <branch_name> --> to rename a branch
git branch -d <branch_name> --> to delete a branch
git branch -D <branch_name> --> to forcefully delete a branch 
git branch --> to show the local branches
git checkout/switch <branch_name> --> to switch from one branch to another
git switch -c <branch_name> --> automatically create and switch to the created branch
git merge <branch_name> --> to merge the whole branch into the currently checked-out branch
git cherry-pick <commit_id> --> lets us copy a specific commit from one branch and apply it to another branch, without merging the entire branch
git ls-files --> to see how many files are tracked by a single branch

# if both branches edited the same lines of the same file, git would stop and ask you to resolve a merge conflict.











git diff --> to show the exact changes we made in files before staging
git diff --staged --> to show the exact changes we made in files after staging
git diff <local_branch/remote_branch> --> to show the exact changes we made in files between the local branch and the remote branch

git push -> to push the files from local to remote
git push -u origin <local_branch_name> --> -u refer to create a branch in remote (use this if you want the same branch name as local in remote branch name)
git push -u origin <local_branch_name>:<remote_branch_name> -> to create a branch in remote with new remote branch name
git push origin --delete <remote_branch_name> --> to delete the branch from remote
git remote prune origin --> it removes references to remote branches that have already been deleted from the remote repository (GitHub)



git clone url --> used to download an existing git repository from a remote sever to your local computer





git fetch --> always going to update the remote tracking branches (to change all the branches)
now, the remote branch get the updated file so merge the master branch with remote branch

To get fast without using git fetch use "git pull", it will change and merge

git fetch --prune does two things:
i. fetces the latest update from the remote repository
ii. removes stale remote-tracking branches that no longer exist on the remote.


git fetch origin main --> to fetch one remote branch
git fetch --all --> to fetch from the branch from all sites like github, gitlab, gitbucket etc.
